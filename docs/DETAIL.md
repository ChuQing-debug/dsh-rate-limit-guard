# 限流守护

当模型提供方返回 PRM/TPM 限额（`RATE_LIMIT`、`HTTP_429`、`QUOTA` 等）时，限流守护会在
当前步骤内接管失败，而不是让请求直接失败：

- **智能等待**：按固定计时器或响应中的 `retry-after` 建议暂停，窗口刷新后自动重试
  同一个请求，已生成的上下文保持不变。
- **轮换密钥**：按顺序把提供方正使用的凭据引用换成密钥池中的下一个值，然后立即
  重试。下一个请求就会使用新值，无需重启。原密钥会先备份，不会丢失。

两种方式由用户在「设置 → 限流守护」中选择，可随时切换，保存后立即生效。

## 工作方式

插件监听 `agent/request-error`，在默认重试策略之前判断失败类型：

1. 命中限额且未超过每步骤重试上限时，记录一条插件日志。
2. 等待模式写入持久化的 `llm/retry` 事件并开始计时；对话中会出现一条带倒计时的
   重试行。计时结束（或用户中止）后写入 `llm/retry-started` 并返回 `retry`，当前
   步骤继续。
3. 轮换模式把刚失败的密钥标记为冷却，按顺序选择下一个不在冷却中的密钥写入目标
   引用，然后立即返回 `retry`。第一次换走不在池中的原密钥时，先把它保存到
   `<目标引用>_RLG_ORIGINAL`，之后它也参与轮换。所有密钥都在冷却时，等待最早恢复的
   那个；没有备用密钥时按配置回退为等待，或把失败交回默认重试策略。同一引用的轮换
   串行执行，刚轮换后 5 秒内到达的失败只用新密钥重试一次，不会重复轮换。
4. 额度/余额耗尽（`QUOTA`、`ACCOUNT_QUOTA`）默认不等待，因为等待无法恢复余额：轮换
   模式换密钥，其他情况直接交回默认处理。
5. 达到每步骤上限后不再接管，交回默认重试策略，避免无限等待。

插件解除时取消正在进行中的计时，不会在卸载后继续触发请求。

## 配置项

| 配置 | 默认值 | 说明 |
| --- | --- | --- |
| 限额响应方式 | 智能等待 | `wait` 或 `rotate`。 |
| 默认等待时长 | 60 秒 | 没有服务端建议时使用。 |
| 优先使用服务端建议 | 开启 | 读取 `providerRetryAfterMs`；缺失时尝试从错误信息解析 `retry after 30s`、`1m30s`、「请在 30 秒后重试」之类的提示，再回退到默认值。 |
| 单次等待上限 | 900 秒 | 更长的等待会被截断。 |
| 每步骤最多重试次数 | 12 | 达到后交回默认策略。 |
| 加入随机抖动 | 开启 | 等待时长随机增加最多 10%（不超过 5 秒）。 |
| 额度耗尽时也等待 | 关闭 | 打开后 `QUOTA` / `ACCOUNT_QUOTA` 也按等待处理。 |
| 额度耗尽的密钥冷却 | 60 分钟 | 轮换模式下该密钥在这段时间内不会再被选中。 |
| 轮换前备份原密钥 | 开启 | 原密钥保存到 `<目标引用>_RLG_ORIGINAL` 并参与轮换。 |
| 目标密钥引用 | `DEEPSEEK_API_KEY` | 轮换时被写入的凭据引用。 |
| 备用密钥引用 | 空 | 每行一个引用，值保存在凭据服务中。 |
| 按提供方映射 | 空 | 每行 `provider=引用`，用于不同提供方读取不同引用。 |
| 无备用密钥时改为等待 | 开启 | 关闭则交回后续处理器。 |
| 只守护这些提供方 | 空 | 逗号或换行分隔，留空表示全部。 |

## 密钥池

设置页只保存**引用名称**，密钥值通过凭据服务写入，不会回显。目标引用是提供方实际
读取的那个（例如 DeepSeek API Key 路由的 `DEEPSEEK_API_KEY`，书生路由的
`SHUSHENG_API_KEY`）。账号登录型提供方（例如桌面默认的 `deepseek-account`）不读取
可替换的 API Key，轮换会记录「无法轮换」并按配置回退为等待。

## 中断记录

- **对话中**：每次等待都会显示一条重试行，包含倒计时、延迟和失败原因。
- **插件日志**：`rate-limit-guard` 前缀的结构化行，含时间、提供方、错误码、模式、
  重试次数和恢复时间。
- **`/ratelimit-log`**：在对话中输入，返回最近 20 条事件的本地时间、动作和说明。

## 排查

- 页面提示「尚未找到配置」：确认插件已在当前 profile 启用，并重启后重试。
- 等待没有发生：检查「只守护这些提供方」是否遗漏了当前提供方，或该失败码不是限额。
- 轮换没有发生：确认备用引用已配置且值与当前不同；账号型提供方不支持轮换。
- 修改无法保存：设置文档只读，或配置文件被外部修改导致版本冲突；重新读取后再保存。
